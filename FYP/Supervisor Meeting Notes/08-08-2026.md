# Supervisor Meeting — 8 August 2026

**Focus:** How to conduct the literature review — the three-matrix methodology, the columns each matrix needs for this specific project, and how they chain into a defensible technical contribution.

**Source material:** *Research Paper Analysis Process* document.

The instruction in §5.2 to **merge the candidate gaps down to 3–4** was not applied in time — all seven were carried forward as independent contributions and criticised on that basis on [[13-09-2026]], which consolidated them into one main gap plus two sub-gaps. Note also that this supersedes the three-table set proposed on [[16-06-2026]]; the Pipeline Mapping table is explicitly dropped here (§7.1).

---

## 1. Outcome in Brief

- The source document requires **three linked matrices**, in this order: **Literature Survey → Dataset Comparison → Research Gap Analysis**.
- The row rules are strict: **one paper per row, one dataset per row, one consolidated gap per row.**
- The standard column sets are insufficient here. Each matrix needs **project-specific columns** that expose whether prior work addresses the four dimensions that define this research: **multi-agent orchestration, volatility memory, liquidity friction, and CSE/frontier-market conditions**.
- The eventual contribution must be **technical** — a framework, architecture, fusion mechanism or optimisation strategy — **not** applying an existing model to a new dataset.
- The Research Gap matrix is **the most important of the three** and carries the greatest emphasis on the technical contribution to the Body of Knowledge.

### The deliverable

| Tab | Matrix | Row rule |
|---|---|---|
| **1** | `Literature_Survey_Matrix` | One research paper = one row |
| **2** | `Dataset_Comparison_Matrix` | One unique dataset/source = one row |
| **3** | `Research_Gap_Analysis` | One consolidated, evidence-supported gap = one row |

---

## 2. Governing Rules

| Rule | Source requirement |
|---|---|
| **Three linked matrices** | Literature Survey → Dataset Comparison → Research Gap Analysis, in that order |
| **One per row** | One paper, one dataset, one consolidated gap — no exceptions |
| **No dataset repetition** | The same dataset must not be re-entered each time a different paper uses it; the Dataset matrix must **compare and contrast** candidates, not list them |
| **Consolidate overlapping gaps** | Gaps appearing across several papers are merged into one row |
| **Technical contribution weighted highest** | The BoK contribution must be a framework/architecture/mechanism, not a model applied to new data |

| ★ **Volatility Handling** | None / rolling volatility / GARCH / EGARCH / FIGARCH / regime detection |
| ★ **Volatility Memory** | Whether persistent/long-memory behaviour is modelled |

| **Evaluation Metrics** | MAE, RMSE, F1, Sharpe, Sortino, drawdown, return |

| **Key Results** | Most important quantitative findings |
| **Strengths** | Genuine methodological strengths |
| **Limitations** | Technical/domain/data limitations |
| **Relevance to CSE Project** | High / Medium / Low + reason |

This becomes the **master literature matrix**.

### 3.1 The six columns that make the gap visible

> **Market/Domain → Multi-Agent Architecture → Volatility Handling → Volatility Memory → Liquidity Handling → Trading Friction**

These are not optional. After 40–60 papers, this column group is what makes the research gap *visible as a pattern in the data* rather than asserted in prose. The expected observation looks like:

> Multi-agent finance papers exist, but primarily evaluate liquid developed markets; volatility papers exist for the CSE but operate independently of agentic decision systems; liquidity studies examine illiquidity statistically but do not integrate friction into agent orchestration.

That is far stronger than claiming *"few papers exist on the CSE."*

| Column | What to analyse |
|---|---|

| **Research Gap** | Precise unresolved technical problem |
| **Gap Type** | Architecture / learning / fusion / volatility / liquidity / sentiment / XAI / evaluation / data |

| **Markets Studied** | Markets covered by existing work |
| **Existing Approach** | What researchers currently do |
| **Limitation of Existing Approach** | Why it is insufficient |
| **Why CSE Exposes the Limitation** | Why frontier/low-liquidity behaviour matters |

| **Required Experiment** | Experiment proving the contribution |

### 5.1 Candidate gaps to investigate

**These are candidates requiring literature evidence — not conclusions already proven.**

| Candidate gap | Possible technical BoK contribution | Potential novelty |
|---|---|---|
| **G01.** Existing multi-agent trading frameworks inadequately model low-liquidity frontier markets | Liquidity/friction-aware agent orchestration framework | **Very High** |
| **G02.** Persistent volatility behaviour is rarely incorporated into agent coordination/decision weighting | Dynamic volatility-memory-aware agent weighting/routing mechanism | **Very High** |
| **G03.** Financial agents generally combine outputs without adapting their influence to market state | Regime-adaptive agent consensus/orchestration mechanism | **Very High** |
| **G04.** Local retail sentiment in low-resource/code-mixed languages is weakly represented in financial multi-agent systems | Localized multilingual financial-sentiment agent / fusion mechanism | High |
| **G05.** Fundamental RAG, technical signals and sentiment are often integrated without handling conflicting evidence explicitly | Conflict-aware multi-agent fusion/consensus mechanism | **Very High** |
| **G06.** Multi-agent strategies are often evaluated using idealised backtests | Friction-aware evaluation simulator with liquidity/volume/slippage constraints | High–Very High |
| **G07.** Agent recommendations can lack transparent attribution of which evidence caused the final decision | Agent-level decision provenance/explainability framework | High |

### 5.2 Do not claim all seven

After reviewing the literature, overlapping gaps must be **merged into perhaps 3–4 defensible major gaps**, as the source document instructs. Claiming all seven as independent contributions is not defensible.

## 6. How the Three Matrices Connect

| Stage | Input | Matrix | What it produces |
|--:|---|---|---|
| 1 | Research paper | **Literature Survey Matrix** | Methodology, market assumptions, volatility treatment, liquidity treatment |
| 2 | Relevant dataset | **Dataset Comparison Matrix** | Whether CSE OHLCV + reports + sentiment + liquidity can actually support the proposed framework |
| 3 | Repeated limitations across papers | **Research Gap Analysis Matrix** | Consolidated overlapping limitations |
| 4 | — | — | **Technical contribution to BoK** |

### 6.1 The contribution to aim for

The literature should be tested against whether it can justify a contribution of this shape:

> **A volatility-memory- and liquidity-friction-aware dynamic orchestration mechanism that adaptively controls the influence of specialised financial agents under changing frontier-market conditions.**

Contrast with:

> ❌ "We combine an LLM, sentiment model, volatility algorithm and technical indicators."

The second is predominantly **integration of existing techniques**. The first proposes a **new orchestration/framework mechanism**, which aligns with the requirement that strong research demonstrate a defensible technical contribution rather than applying existing methods to another dataset.
