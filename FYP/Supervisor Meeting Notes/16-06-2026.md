## 4. Recommended Topic and Framing

### Working title

> **A Friction-Aware Multi-Agent Financial Decision Support Framework for the Colombo Stock Exchange using Volatility Memory, Localized Sentiment, and Low-Liquidity Execution Simulation**

Shorter form for general use:

> **A Friction-Aware Multi-Agent Decision Support Framework for Frontier Equity Markets: A Colombo Stock Exchange Case Study**

This framing is deliberately **not** "trading bot" or "strategy orchestration". It avoids overclaiming, avoids presenting the system as financial advice, and positions the work as a **research prototype / decision-support simulation framework**.

### Task–Domain–Constraint structure

| Component | Definition |
|---|---|
| **Task** | Multi-agent financial decision support / strategy orchestration |
| **Domain** | Colombo Stock Exchange as a frontier equity market |
| **Constraint** | Dynamic volatility memory and low-liquidity execution friction |

This is good research framing because **the constraint is not decorative**. Existing frameworks generally assume deep, liquid, frictionless markets, whereas the CSE has low liquidity, volatility shocks and limited retail participation.

### Where the novelty must come from

Not from "using LangGraph". The novelty sources, in order of strength:

| Novelty factor | Strength |
|---|---|
| Reusable framework beyond one stock or one prediction task | **Very strong** |
| Low-liquidity slippage / execution friction | **Very strong** |
| CSE as a frontier / low-liquidity market | Strong |
| Dynamic volatility memory | Strong if implemented properly |
| Local multilingual / code-mixed sentiment integration | Strong, but data-risky |
| Multi-agent critique-correction / debate mechanism | Strong, but overlaps with TradingAgents |

If implemented properly this moves from a normal 80–89 project into potential 90+ territory, because it becomes a **general framework for frontier-market financial intelligence** rather than a model trained on CSE data.

### Why the intersection is defensible

The strength is not that the project uses LLMs, RAG, sentiment analysis and algorithms together. It is the **intersection**:

> **Multi-agent AI + Colombo Stock Exchange + low-liquidity frontier-market behaviour + volatility/friction-aware decision simulation**

Multi-agent financial trading generally is becoming active — TradingAgents, P1GPT, QuantAgent, QuantAgents and MountainLion all show a growing research direction. But **multi-agent trading under frontier-market liquidity friction is much less saturated.** That is where the real novelty sits.

## 5. Risks and Weaknesses

### 5.1 The scope is overloaded

The current version attempts to include all of:

- OHLCV forecasting
- RAG over annual reports
- multilingual sentiment analysis
- multi-agent orchestration
- volatility modelling using ARMA-FIGARCH
- low-liquidity execution simulation
- portfolio optimisation
- trading strategy evaluation
- social media scraping
- possible LangGraph implementation

**That is too much for an FYP unless tightly scoped.**

### 5.2 Duplication risk with TradingAgents

The proposed architecture — fundamental, sentiment, technical, risk and trader agents — is currently **too close to TradingAgents**, which already uses specialised LLM agents with debate, risk management and trading decisions. The idea is well aligned with a current research direction, but *"TradingAgents for CSE"* cannot be the contribution.

The reframing in §4 moves the novelty away from "multi-agent bots" and toward **market-friction modelling, volatility memory and frontier-market decision support**.

### 5.3 Dataset availability — the biggest technical issue

The proposal itself notes that the CSE historical OHLCV dataset **lacks intraday order queues and historical bid-ask spreads**.

> ⚠️ Therefore "realistic order-book execution" cannot honestly be claimed unless actual intraday/order-book data is obtained. Otherwise the work must explicitly state that it uses **proxy-based liquidity simulation**.

| Dataset / source | Usefulness | Risk |
|---|---|---|
| **CSE OHLCV historical data** | Essential for technical/risk agents | Daily data may be too coarse for execution friction |
| **CSE annual/quarterly reports** | Useful for fundamental RAG agent | PDF extraction noise and table parsing errors |
| **Localized retail media / Reddit / Facebook** | Novel for sentiment | Access, ethics, noise, sparse finance-specific Sinhala/Tamil data |
| **TradingAgents Cache DB** | Useful baseline for multi-agent comparison | US-market bias; not directly comparable to CSE |
| **Sinhala / banking sentiment corpora** | Useful for pretraining/validation | Domain mismatch with capital-market sentiment |

The dataset strategy correctly states that no single dataset solves the gap, and proposes combining CSE historical data, localized media streams, financial reports and the TradingAgents Cache DB for benchmarking. **But the project must not depend on unavailable data.**

## 6. Recommended Scope

### 6.1 Minimum viable research system

| Agent | Keep? | Reasoning and constraint |
|---|---|---|
| **Technical Analyst Agent** | ✅ Keep | Easy to implement and evaluate using OHLCV — RSI, MACD, moving averages, returns, volatility indicators |
| **Sentiment Analyst Agent** | ✅ Keep, scope carefully | Strong novelty if localized/code-mixed. Use Reddit/Facebook/news only if collection is ethical and feasible; manual annotation of a smaller dataset may be needed |
| **Fundamental RAG Agent** | ⚠️ Keep as limited/optional | Useful, but PDF parsing can consume too much time. Restrict to selected companies; CSE provides annual report access officially |
| **Volatility Risk Agent** | ⚠️ Keep, simplified | Start with volume-based liquidity proxies and rolling volatility before attempting FIGARCH |
| **Trader / Portfolio Manager Agent** | ✅ Keep | **This is the main framework contribution** — the orchestrator that combines conflicting signals and produces explainable decisions |

### 6.2 Stage the volatility component

Do not begin with full ARMA-FIGARCH unless mathematically confident:

| Stage | Method |
|---|---|
| 1. Baseline | Rolling volatility / EWMA |
| 2. Intermediate | GARCH |
| 3. Advanced | FIGARCH or fractional volatility memory |

### 6.3 Universe

Focus on **10–20 selected CSE stocks**, preferably liquid / high-market-cap names first. Attempting to cover the entire CSE will weaken the project.

### 6.4 Target final scope

> Select 10–20 CSE-listed stocks, collect OHLCV data, extract limited sentiment from localized sources, optionally process annual reports for fundamental signals, build a multi-agent decision framework, simulate low-liquidity execution using volume/slippage proxies, and evaluate whether the multi-agent framework outperforms single-agent and non-friction-aware baselines.

That version is novel, feasible and defensible.

### 6.5 What separates 90+ from 80–85

Reaching the top band requires producing:

- a reusable multi-agent orchestration framework
- a CSE-specific liquidity-friction simulator
- volatility-memory modelling
- agent ablation experiments
- transparent agent decision logs
- benchmarking against single-model and non-friction-aware baselines

Without these it falls into the **80–85 range** as an integration of existing components.

## 7. Evaluation Design

The project must **not** be evaluated only by accuracy. It is a financial decision-support framework and should be evaluated as one.

| Evaluation area | Metrics |
|---|---|
| **Forecasting / signal quality** | Directional accuracy, F1 for up/down movement, RMSE/MAE if predicting returns |
| **Trading simulation** | Cumulative return, Sharpe ratio, maximum drawdown, turnover |
| **Liquidity friction** | Slippage penalty, volume-adjusted execution cost, failed/partial execution simulation |
| **Agent contribution** | Ablation: remove sentiment agent, remove volatility agent, remove RAG agent |
| **Explainability** | SHAP/LIME for sentiment/forecasting, agent rationale logs, decision traceability |
| **Robustness** | Performance under high-volatility periods vs normal periods |

The proposal already mentions cumulative returns, Sharpe ratio, maximum drawdown, agent logs and consensus metrics in its literature matrix — these can be extended into a proper evaluation framework.

## 8. The Alternative Topic

**Multi-Horizon Sequential Price Forecasting on the CSE via Explainable Localized Multilingual Sentiment Fusion**

A good backup, but likely to remain in the **80–85 range** unless broadened. Stock prediction using technical indicators, sentiment, LSTM/Transformer models and explainability is already heavily explored; a 2025 review confirms ML/DL for stock market prediction is a broad, well-covered area. CSE-specific work already exists on public sentiment analysis for CSE prediction and on Sri Lankan stock prediction using economic indicators and sentiment.

**The danger** is that it reduces to:

> ❌ "I used LSTM/Transformer + sentiment + SHAP to predict stock prices."

### Where novelty could still come from

| Novelty factor | Strength |
|---|---|
| Localized Sinhala/Tamil/Singlish sentiment | **Strong** |
| Code-mixed financial sentiment fusion | **Strong** |
| Generalisable sentiment-fusion framework | **Strong** if built as a reusable pipeline |
| Multi-horizon forecasting | Moderate |
| CSE-specific forecasting | Moderate |
| Explainability | Moderate |

The proposal identifies multilingual banking reviews, Sinhala sentiment comments and localized media as sources, but notes these are domain-limited and may lack capital-market vocabulary. The real challenge is therefore not model training but building a **localized financial sentiment representation pipeline** for a low-resource, code-mixed setting.

## 9. Literature Review Strategy

### 9.1 Do not search the full title

The exact phrase *"Multi-Agent Strategy Orchestration on the CSE under Dynamic Volatility Memory and Low-Liquidity Friction"* is too specific — Google Scholar and Semantic Scholar will return almost nothing. Break the topic into **research blocks** and search each separately.

**Better search title:**

> **Multi-Agent Financial Decision Support for Frontier Equity Markets under Volatility and Liquidity Constraints** — with *A Colombo Stock Exchange Case Study* as the sub-framing.

### 9.2 Structure the review in three layers

The objection *"there are very few CSE papers, so I cannot find a literature review"* is not valid. The review must not depend only on CSE papers.

| Layer | What to review |
|---|---|
| **Layer 1 — CSE / Sri Lankan market studies** | CSE prediction, volatility, sentiment, investor behaviour, market liquidity |
| **Layer 2 — Global financial AI / multi-agent trading** | TradingAgents, LLM agents, RAG-based financial analysis, portfolio decision systems |
| **Layer 3 — Low-liquidity / frontier-market constraints** | Slippage, volatility clustering, liquidity friction, low-volume trading, market microstructure proxies |

**Use CSE papers for the domain gap; use international papers for the technical methods.**

Mapped to the system components:

| Literature area | Purpose in this topic |
|---|---|
| CSE stock prediction papers | Show what has already been done locally |
| CSE volatility / liquidity papers | Justify why the CSE is not a perfect/liquid market |
| Multi-agent financial AI papers | Justify the agentic architecture |
| LLM / RAG financial analysis papers | Support the fundamental analyst agent |
| Sentiment analysis papers | Support the sentiment analyst agent |
| Market microstructure / slippage papers | Support the low-liquidity friction simulator |
| Portfolio optimisation / backtesting papers | Support the trader/portfolio manager agent |

### 9.4 Search tool workflow

**Google Scholar**

1. Start broad — e.g. `"multi-agent" "LLM" "financial trading framework"` — then open the best 3–5 papers.
2. Use **Cited by** on each relevant paper to find newer work built on it.
3. Use **Related articles** to find similar work.
4. **Vary the wording** — do not always use "CSE": try `"Colombo Stock Exchange"`, `"Sri Lankan stock market"`, `"ASPI"`, `"S&P SL20"`, `"frontier equity market"`, `"emerging stock market"`, `"illiquid stock market"`.
5. **Do not filter by year at first.** Search unfiltered, then narrow to 2021–2026 or 2023–2026. For CSE-specific work the recent count may be low, so older papers still help establish domain background.

**Semantic Scholar** — search one concept at a time (`multi-agent LLM financial trading`, then `Colombo Stock Exchange stock prediction`, then `Colombo Stock Exchange volatility`, then `stock market liquidity transaction cost slippage`), filtering to Computer Science / Economics / Business and 2023–2026, sorted by Relevance then checked against Highly Influential Citations.

| Feature | How to use it |
|---|---|
| **TLDR** | Quickly judge whether the paper is relevant |
| **References** | Find older foundation papers |
| **Citations** | Find newer papers |
| **Highly Influential Citations** | Find papers that shaped the field |
| **Related Papers** | Expand the literature set |

### 9.6 How to word the gap

❌ **Never write:** "There is no research on this topic."

✅ **Write instead:**

However, limited work integrates these into a friction-aware, multi-agent decision-support framework for a low-liquidity frontier equity market such as the Colombo Stock Exchange.

Equivalently, for the literature chapter:

> Existing studies separately address multi-agent financial AI, CSE volatility, liquidity-based return prediction, financial RAG, and multilingual sentiment analysis. However, limited work integrates these into a friction-aware multi-agent decision-support framework for the Colombo Stock Exchange under volatility-memory and low-liquidity constraints.

**No single paper covers the full topic — do not claim otherwise, and do not claim the topic is untouched.**
