## 5. Proposed Technical Contribution

> An adaptive orchestration mechanism that dynamically changes the weighting/influence of heterogeneous financial agents according to market liquidity, volatility/persistence and agent confidence.

**Formalisation:**

$$w_{i,t} = f( L_t,\ V_t,\ P_t,\ C_{i,t} )$$

where:

- $L_t$ = liquidity state
- $V_t$ = volatility
- $P_t$ = persistence
- $C_{i,t}$ = agent confidence

i.e. $w_{i,t} = f( Liquidity_t,\ Volatility_t,\ Persistence_t,\ Confidence_{i,t} )$.

This is substantially stronger than merely connecting *RAG + technical indicators + FIGARCH + sentiment + trader agent*.

## 6. Decision — Drop the Sentiment Component

**Final decision: drop the sentiment aspect.**

### 6.1 Sentiment was never the source of the strongest novelty

Sentiment had become one of the **weaker** components, because it introduced an entire second research problem:

- primary data collection
- manual annotation
- annotator disagreement
- ethics / platform-access issues
- language adaptation
- code-mixed NLP
- dataset validation
- another independent ML problem

That could easily consume half the FYP — and none of it directly proves the main proposed contribution.

Dropping it removes substantial risk while **preserving everything that carries the novelty**:

| Retained | |
|---|---|
| Liquidity novelty | ✅ |
| Volatility-memory component | ✅ |
| Adaptive orchestration | ✅ |
| Heterogeneous agent interaction | ✅ |
| Friction-aware evaluation | ✅ |

### 6.2 Does this reduce agent diversity?

Slightly — but this is **not a novelty problem**. Fundamentally different information sources remain:

$$Technical \neq Fundamental \neq Risk \neq Liquidity$$

These agents represent genuinely heterogeneous evidence. The research question is not *"How many agents can I connect?"* but:

> **How should heterogeneous agent outputs be coordinated under changing market conditions?**

**Three or four well-defined agents are better research than six loosely justified agents.**

### 6.3 Fewer agents improve experimental validity

With too many components, a performance improvement cannot be attributed. If a system containing a technical model, sentiment model, RAG, fundamental analysis, FIGARCH, liquidity model, RL and an LLM manager improves returns by 5%, **what caused it?** Very difficult to establish.

A narrower architecture permits proper ablation:

| Configuration | Weighting scheme |
|---|---|
| **Baseline 1** | Equal weight |
| **Baseline 2** | Static learned weight |
| **Proposed** | Dynamic state-aware weight |

Then ablate each state input:

$$\begin{gather*}
Proposed - Liquidity \\
Proposed - Volatility \\
Proposed - Persistence \\
Proposed - Confidence
\end{gather*}$$

Now the actual technical contribution becomes **measurable**. That is much stronger research.

## 8. Dataset — The Critical Blocker

### 8.1 Requirement

A **sufficiently long, clean, legally usable individual-stock CSE historical dataset**, covering enough companies over enough years, containing:

| Field | Necessity |
|---|---|
| Date | Required |
| Ticker | Required |
| OHLC | Required |
| Volume | Required |
| Turnover / trading value | Required |
| Number of trades | Ideally |
| Market capitalisation | Preferably |

This is critical because the dataset underpins **liquidity state, volatility, regime identification, adaptive orchestration, portfolio simulation, backtesting and walk-forward evaluation**.

> ⚠️ **If only 12–18 months of data is available, the whole experimental design becomes questionable.**

### 8.2 Availability Audit

| Statement | Verdict | Evidence |
|---|---|---|
| CSE historical share-price data exists | ✅ **Correct** | CSE publishes daily share-price information containing stock symbol, high, low, close and share volume. Official CSE reports confirm this. ([CSE daily report](https://cdn.cse.lk/cms-internal/news/1rkfSshc3B2hCj71_14Jul2022035042GMT_1657770642808.pdf)) |
| Historical values exist for individual CSE stocks | ✅ **Correct** | Daily security-level records are available through CSE material and its public data interface. |
| High, Low, Close and Volume are available | ✅ **Confirmed** | Official CSE daily share-price lists explicitly contain high, low, close and volume. ([CSE daily report](https://cdn.cse.lk/cms-internal/news/1rkfSshc3B2hCj71_14Jul2022035042GMT_1657770642808.pdf)) |
| **Open is always available in the same official historical files** | ⚠️ **Not universally confirmed** | The verified official daily share-price PDFs show high, low, close, previous close and volume — but not always an explicit opening-price field. |
| CSE has endpoints returning historical stock/chart data | ✅ **Yes** | The CSE public interface includes `chartData` and `companyChartDataByStock` with a period parameter. Note: available API documentation is **community-produced**, not formal CSE developer documentation. ([GitHub](https://github.com/GH0STH4CKER/Colombo-Stock-Exchange-CSE-API-Documentation/blob/main/README.md)) |
| A ready-made OHLCV dataset exists | ✅ **Yes, but coverage varies** | A CC-BY dataset contains 289 CSE-listed stocks and 71,044 OHLCV rows — but only for Feb 2025 – Feb 2026. ([Hugging Face](https://huggingface.co/datasets/tharu-jwd/cse-market-data)) |
| Long historical OHLCV datasets exist | ✅ **For some securities / commercial sources** | Kaggle has 2010–2025 OHLCV but only for three stocks; ICE offers CSE daily historical data back to February 2012 commercially. ([Kaggle](https://www.kaggle.com/datasets/bhanukadilshan/sri-lanka-stock-dataset-2010-to-2025)) |
| Scraping web pages is therefore necessary | ❌ **Not necessarily — not recommended first** | Prefer existing datasets, official CSE data/interface, or an authorised/commercial feed before scraping. |
